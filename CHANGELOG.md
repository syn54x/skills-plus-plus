# @syn54x/spp

## 2.9.0

### Minor Changes

- 27003e7: `harden` now drops a Test scenario an existing test already covers, merges scenarios that differ only by input, and names the test a new scenario replaces.
- 27003e7: `review` now accepts a criterion that `harden` marked as already covered by an existing test, and for a `break not run` mark it runs the deliberate break and reports the criterion unproven unless the named test turns red. The review panel's testing reviewer accepts both forms of the mark and leaves the break to `review`.
- 27003e7: `tdd` now declines a test another test already covers, and refuses tests of constants, message wording, framework behaviour and trivial code.
- 27003e7: Added `/test-audit`, which reads a test suite, reports the tests another test already covers, and files the removals you pick as issues for triage.
- 27003e7: The review panel's `testing` Persona now reports a test the pull request adds that another test already covers, and names the test to keep.
- 27003e7: Triage now proves an issue filed by `/test-audit` by breaking the code in a scratch copy and running the Keeper, and closes it as `wontfix` when the Keeper stays green.

### Patch Changes

- a0b1f1f: In `auto-grill`, every veto line now opens with a handle (`V1`, `V2` and so on, numbered across the stop, lines that depart from common practice first), so "strike V3" is a complete reply. In the Claude desktop app, each drawing is sent right after its own question, and a button sends the letter answer (`1B`) on its own line, so two clicks no longer run together.

## 2.8.0

### Minor Changes

- e9ef54f: `/chief-of-staff` now keeps a Wiki: a folder of dated, linked markdown pages above your repos, with one page per goal and an index. It recommends an existing Wiki and uses it only on your yes, cites what a repo records instead of copying it, and supersedes a changed claim instead of rewriting it.
- e9ef54f: `/chief-of-staff` now sends work out instead of doing it: it starts a Build session for an Epic or One-off and a triage session for a filed issue, answers a waiting session as your Proxy when a source settles the question, relays the ones that touch the gate, runs research in background subagents, and asks you to type the user-invoked steps.
- e9ef54f: Added `/chief-of-staff`, an experimental session role that acts as your Proxy for the goals you give it: it settles what the record settles, brings you Escalations, Challenges and a veto list, and asks before merging to a protected branch, releasing or closing an Epic.
- 4ab3f54: A `grilling` Round can now be answered with letters: every option sits on its own line as `A:`, `B:` and so on, the recommended one first, with a `Rests on:` line naming what the recommendation assumes, and a reply such as `1A 2B` or `all` answers the whole Round, with a caveat after any letter. Each Round after the first reads back the replies that changed the plan, says how many choices are settled and which are held back, and lists the facts it looked up with their sources. The closing restatement marks each line with its source (you, the record, or the agent's inference) and puts the inferred lines last as the ones to check. In `auto-grill`, the veto list stands in for the list of looked-up facts.

## 2.6.0

### Minor Changes

- 9bdb63d: `/build <N>` in the desktop app now asks one question first: run the build here, or in a sub-session. It recommends the sub-session when your session has already started other sessions or sits outside N's checkout. A sub-session starts in the checkout of N's repository (found one folder down when you are above it, or asked when there are none or several) and runs `building` there, and an answer you give in your own session to its question is passed on to it in your words. In a terminal nothing changes: `/build` builds here without asking. The choice lives in a new shared skill, `delegating`.
- 9bdb63d: A session can now start a build with the new `building` skill: tell it "use building for #N" and it builds N exactly as `/build N` does, so an agent such as a Chief of Staff session can start a build without anyone typing `/build`. The build's steps, references and credits move from `build` to `building`; `/build` still works as before and now hands the issue to `building`.
- 9bdb63d: Every worker is now a subagent. The `desktop` and `bg` Drivers are gone, and so is `--driver`: `spp dispatch <issue>` takes no flags and writes the brief without starting `claude --bg`, `spp plan` no longer records or renders a Driver, and `spp next` no longer puts a `driver` on its `dispatch` actions. Passing `--driver` to either command is a usage error. `building` no longer asks which Driver to use at the first Wave; its approval question now comes first in its message, so a parent session sees it. An Epic whose plan comment still records a Driver builds as before, with subagent workers.
- 9bdb63d: A build resumed after its session died now asks about the work its lost workers left behind. `spp next <epic> --resume` returns each Sub-issue that is claimed, with no open or merged pull request and no assignee, as a `hand-back` saying `worker lost`, and `building` passes `--resume` on the first `spp next` of each run, so you choose whether to hand the issue back or start a worker on it again. `spp next`, `spp wait`, `spp wave plan` and the Epic board no longer read the `claude agents` session list: `spp wait` no longer prints `t-<N> done` lines, and the board lists only its own session's subagent workers, so its `attach` button is gone.

### Patch Changes

- 9bdb63d: `spp next` and `spp wave plan` take `--running <tickets>`: the tickets the build started a worker on, until that worker reports back, count as in flight, so neither command dispatches them again, and a ready ticket that overlaps one is held. Without the flag nothing is held that way. `building` keeps that list and passes it on every `spp next`, and starts each worker's Agent description with `t-<N>`, so the Epic board links the worker to its row. The board's worker entries drop their `kind` field, and a failing agent list read shows as `agent list: <message>`.
- 9bdb63d: `spp next` and `spp wave plan` share one parser and one error message for the flag. `building` passes each running ticket in the form the `dispatch` action named it, and resumes a worker by the agent id its Agent call returned.
- 9bdb63d: A resumed build no longer starts a fresh worker on a branch another worker left. When a fix round, a rebase or a settled design needs a worker that died with an earlier session, `building` asks you whether to hand the issue back or take the pull request over. `spp brief`'s first step again only cuts `sdd/<N>-<slug>` from the base and confirms it, and a restarted lost worker starts on that fresh branch, so a branch the lost worker pushed is yours to delete or the issue goes back. `spp next --running` now holds a running ticket in any state, landed included: neither it nor its fix pull requests are routed again while its worker works, and `main-gate` waits for it. `spp wave plan --running` holds each one until it lands, with the reason `running, its worker has not reported back`. `building` keeps each worker's agent id for the rest of the session and puts an issue back on the running list when it resumes its worker.
- 9bdb63d: `building`: each answer to the dead-worker question now leaves a mark `spp next` reads, so the same `fix` or `merge` stops coming back. Taking a pull request over puts its issue on the running list until you say you are done; handing back a fix pull request closes it with its open findings, so the main gate can run. `spp brief`'s first step now stops BLOCKED when origin already has the ticket's branch or cannot be reached, and the brief tells the worker never to force-push.
- 9bdb63d: Every question `building` stops on now opens with one line, `#<N> waits on you: <question>`: the first Wave's approval, a lost worker, a red Verify after a merge, a design to settle and an issue it cannot build. `delegating` relays your answer from a parent session to any of them, not only the Wave approval. `/build` on a Sub-issue or a raw issue now stops with the reason before it asks where to run, and starts no sub-session. Restarting a lost worker removes its local worktree and branch once you agree.

- 9435c98: The review skill now starts its fresh reviewer with the pull request and nothing else, so an orchestrator no longer adds its own criteria, round histories or setup notes to the reviewer's prompt.

## 2.3.0

### Minor Changes

- 2d5b628: The epic board now lists an Epic's fix pull requests in a `Fixes` group after the Waves: one row per open or merged fix with a `fix open` or `fix merged` chip, its number, the Sub-issue its `Refs` line names (or `unattributed`) and a `PR` button that copies its link. While the Epic has any fix, the board header and the status line end with the open count, as in `12/12 merged · 3 fixes open`. A failing pull request read keeps the ticket rows and shows its error. A board stored by an earlier version is dropped and redrawn on the next refresh.
- 2d5b628: `spp merge` now merges a Fix pull request: one that closes no Sub-issue of its Epic but `Refs` a Sub-issue, with a trusted passing verdict on its head, the Epic's integration branch as base and passing checks. It writes nothing to the wave comment, and a pull request that closes no issue and refs no Sub-issue is refused.
- 2d5b628: `spp next` now routes an Epic's Fix pull requests the way it routes a slice: `gate` when its checks pass and its head has no verdict, `fix` once after a failed head (naming the failing runs when checks are the cause), `hand-back` naming the pull request after a second failed head, `merge` on a passing verdict, and `wait` while its checks are pending or its Sub-issue's worker is running. An unattributed fix is never gated or merged: it is reported under `wait`, or `stuck` when nothing else is in flight, with the way out (add `Refs #<Sub-issue>` to its body, or close it). `main-gate` now prints only once no fix is open. The action shape is unchanged.
- 2d5b628: The `review` skill now gates a Fix pull request: one with no closing line that opens `Refs #N` for a Sub-issue and targets its Epic's integration branch gets both verdicts, the Sub-issue's Verify block, and a verdict marker recorded with `spp verdict --ticket N`. `build`'s Main gate follows `spp next` for fixes (`gate`, `fix`, `merge` or `hand-back`) and `spp merge` merges them, so the orchestrator no longer merges a fix by hand.
- 2d5b628: `spp status` now lists an Epic's Fix pull requests: trusted pull requests into its integration branch that close no Sub-issue, open or merged (ADR 0011). The text view prints them under a `Fixes` heading after the Layers, one line each with its state, its number and the Sub-issue its `Refs` line names or `unattributed`, and the header line ends with the open count, as in `(3 fixes open)`; with no fixes it prints neither. `--json` carries the same list as `fixes` on the Epic state, each with `ticket` set to the Sub-issue's URL or null. `spp wait` exits with a change line when a fix appears, merges or goes (`#77 OPEN -> MERGED`), gets a new head after a fix round or gets the gate's verdict (`#77 OPEN -> OPEN (new head)`). The snapshot makes one more GraphQL request per repo of the Epic (its own, each Sub-issue's and each the plan names) for the list, only when the plan comment records an integration branch; a repo that is not there or not readable is warned about on stderr once and loses only its fixes, while any other failure fails the command. `snapshot.ts` exports `pullRequestsArgs(snapshot)`, `fixRepos`, `withPullRequests` and `readPullRequests` for the epic board.
- 3c14c8d: `/to-tickets` now checks the set for values worked out twice. When one Sub-issue works a value out from another module's output (a client inferring each row's state from a summary the server returns), it asks whether the module that holds the inputs should produce the value itself. If so, the producer gains a Produces line or a Sub-issue of its own before anything is released, and the consumer reads the value. A derivation you meant to keep is yours to accept.

### Patch Changes

- 8856ea4: `spp dispatch <issue> --driver subagent` now refuses a folder that is not inside a git repository, before it reads GitHub. The `spp:worker` agent cuts its worktree from the session's folder, so every worker started from such a folder failed with `Cannot create agent worktree: not in a git repository`. The refusal says to run `/build` from inside the checkout of the repository that owns the issue, or to choose another Driver. The `bg` and `desktop` Drivers are unchanged.
- 2d5b628: A Fix pull request in `EpicState.fixes` now carries its `gate` on the current head, computed once, and `spp next` reads it. The way out for an unattributed fix names `Refs #<Sub-issue>` only, since `Closes` on a closed Sub-issue makes the pull request that ticket's own.
- f197712: The stop hook, `spp verify --check`, now ends its refusal on a `Stop` event with one more sentence: if this is a worker's worktree and you are not that worker, cd back to your own checkout and stop again. The hook judges the tree the session stands in and cannot tell whose work is there. An orchestrator whose shell was left inside a worker's worktree was therefore refused at the end of every turn until the worker committed, and one run polled through 18 fix rounds that way. `build` on Claude Code now tells the orchestrator to read a worker's worktree with `git -C <path>` and to stay out of it. A `SubagentStop` refusal and a run by hand print what they printed before, and which stops are refused has not changed.
