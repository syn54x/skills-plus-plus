# Self-improvement runs in attended sessions under two modes

Until now, **Skill feedback** came only from `close-epic`, and a person approved each body before it was filed. That kept anything from leaking, but nothing could be filed while a build was still running or while a worker ran unattended, so a defect showed up only after it had cost a whole Epic (one Stop-hook defect ran through 18 fix rounds before anyone filed it). spp now records a **Signal** whenever something a skill step made is later corrected, and two settings govern what happens to those Signals. The **Self-improvement mode** is set per repo in the Routing block: Off, Anonymous or Full Detail. It sets the most a report may say about the repo's work. The **Submission mode** is set per person: Auto or Review. It decides whether reports are filed under that person's GitHub account without anyone looking. The two are split because the repo owns its data while each person owns their account: one committer must not be able to switch on unattended filing under every teammate's name. Signals are collected only in an **Attended session**. CI never counts, and every worker or subagent started from an attended session does, so the consent a person gave by starting the work reaches everything it starts. Whether a session is attended is decided once, where the work starts, and passed down by spp, because the harness signals for it are undocumented and differ between child processes. A secrets scan blocks every report in every mode. Auto in a private repo falls back to Review. Approving each body lost because it blocks live and unattended filing, which is the whole point of the change. A single repo-level switch lost because filing happens under a person's own name.
