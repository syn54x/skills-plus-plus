# A fix pull request is found by its shape, not by a record

A **Fix pull request** answers Main gate findings: a worker opens it into the Epic's integration branch with `Refs #<Sub-issue>` in its body, since the Sub-issue it belongs to is already closed. Until #303, `spp` saw only pull requests that close a Sub-issue, so every fix was invisible to `spp status`, `spp next` and the epic board, and the orchestrator tracked, reviewed and merged each one by hand; one Epic ran twelve that way while the board read every ticket merged. `spp` now treats any trusted pull request into an integration branch that closes no Sub-issue as a fix, open or merged, at any stage of the build, and reads nothing else to find it. The `Refs` line only says which Sub-issue a fix belongs to; a fix without one still shows, as unattributed, and holds the Main gate until it names its Sub-issue. Recording each fix on the wave comment at merge lost because a record is written by the path that merges, and the failure being fixed was exactly a pull request that no `spp` path had touched. Finding fixes by their `Refs` line alone lost for the same reason: a fix that forgets the line would be invisible again. The price is one more pull-request list in the snapshot query, since closing references and cross-references cannot find a pull request that names no issue.
