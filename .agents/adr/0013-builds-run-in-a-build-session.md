# Builds run in a Build session and every worker is a subagent

A build now runs in a **Build session**: the session `/build` was typed in, or a sub-session that `build`'s hand-off to `delegating` starts. `build` stays the one user-invoked entry and `delegating` only chooses where the build runs; `building` does the work and never asks where. Every worker is an isolated subagent, one per **Sub-issue**, in a worktree of its own. Before this, a Wave picked a **Driver** by capability: a desktop linked session, a background session, or a subagent. Desktop linked sessions lost because every Wave after the first waits on a user message before it can start, which stalls an unattended build. Background sessions lost because spp's own background path passed no tier, so a worker's model and effort could not be set per ticket, and keeping a second worker path was not worth adding one. A subagent starts from the Build session with no user message and takes its tier, and every driver already kept the same contract (a ticket number in, a pull request out, all state in GitHub), so dropping two of them removes the `--driver` choice without changing what a worker does. The **Driver** term is retired with them.
