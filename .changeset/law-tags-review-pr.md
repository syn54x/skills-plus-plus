`review-pr`'s Quality verdict now judges against the repo's declared **Laws**: the documents on the `Laws:` line of the `<!-- sdd-routing -->` block in `CLAUDE.md` or `AGENTS.md`, or, when that line is absent, `CLAUDE.md`, `AGENTS.md`, `GLOSSARY.md`, `CONCEPTS.md`, `CODING_STANDARDS.md`, `CONTRIBUTING.md`, and the ADR directory (`docs/adr/`, or the path the repo's domain docs name), the same fallback `implement-issue` and `review-panel` state, plus the pattern the brief named. Each line of the PR body's `## Laws` section is a claim the reviewer verifies against the diff: an `n/a` on a law whose trigger the diff hits is a finding tagged with that law, and a PR body with no `## Laws` section is an Important finding tagged `[skill#Laws section]`, as a missing `Verify block corrected:` line already is. Every finding, Spec and Quality, carries a **Law tag** right after its severity, `- <severity> · [<source>#<id>] · <file:line at sha> · …`, where the source is a Laws-line path, `ADR-<nnnn>`, `epic`, `ticket`, `cited`, `skill` (a rule of the SDD skills themselves, such as `[skill#Laws section]`) or `none`; the posted-review template shows it on both verdict blocks, a scoped re-review's `ADDRESSED` / `NOT ADDRESSED` lines carry none, and its new findings do. The tag costs the reviewer nothing and gives `close-epic`'s retro a source to count fix-round findings by (epic #55).
