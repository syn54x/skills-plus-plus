`close-epic`'s retro now counts fix-round findings by cause. Schema `sdd-retro/3` adds `fix_rounds.by_cause`, which reads every finding in a failed `review-pr` verdict on a ticket PR, any severity, and groups it by its Law tag's source: a repo path keeps its path (`AGENTS.md`, `ADR-0009`), `ticket` keeps its section (`ticket#Interfaces`), `epic`, `cited`, `skill` and `none` collapse to one key each, and an untagged finding counts as `none`; it is `null` exactly when `fix_rounds` is. A new `scripts/sdd-by-cause.py` does the counting from stdin, so `scripts/sdd-retro-check.sh` checks it against a fixture without `gh`. RETRO.md's Reading-it table maps each cause to the step it points at, and `close-epic` §4 cross-checks every key against the Laws line: a Law the worker was given counts toward the new `law-read-not-checked` category, a repo file the Laws line never named toward `law-not-in-read-list`, and `none` toward neither. Skill feedback carries the totals by family name only (`by cause: repo n · epic n · ticket n · cited n · skill n · none n`), so no path leaves the repo, and `feedback-guard-check.sh` proves the guard passes that line under every profile. Older `sdd-retro/2` comments simply lack the key.
