A **Claim** is now a mark the tracker records, not an assignment (ADR 0006). On GitHub and GitLab the mark is the label `claimed`; the local tracker keeps `Status: claimed`. A ticket is **held** when it carries the mark or an assignee; agents write only the mark, and a human's self-assignment still counts. `sync-progress` owns claim and unclaim (it creates the label idempotently before the first claim), `implement-issue` claims and resumes by the mark with the holder named on the progress comment's Worker line, `build-epic` no longer claims before dispatch (the worker does) and its `ready.sh` reports `claimed` and runs under current `gh`, `setup-syn54x-skills` creates the label and writes the new readiness line into the routing block, and `close-epic`'s retro reads claim time from the first `labeled claimed` event with the `assigned` event as the fallback. The cloud workflow's guard now fires on whichever of `ready-for-agent` and `size:S` lands last and skips a held issue, so label order no longer matters. A new `scripts/check-sdd-ready.sh` pins the ready queue through the same stub `gh` as the retro check, now shared at `scripts/fixtures/gh`.
